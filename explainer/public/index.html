Who does what?

The helper writes possible examples. The small model learns from the selected examples. The software connects those steps.

Claude or GPT
A capable helper proposes rewrites of existing worked solutions. We will record the exact model version after the pilot.
Qwen3-0.6B
The starting student model. The pilot will compare feasibility with 1.7B before choosing one model for every condition.
Transformers + PyTorch
Python tools that load the student, generate answers and run training. Transformers also gives us the student’s tokenizer.
PEFT + LoRA
PEFT is the library that adds LoRA. LoRA learns small weight additions while the original model stays frozen.
Ollama + Qwen3-8B
A local fallback for writing candidate solutions. Ollama runs models on our computer. The helper and student can belong to different model families.

    What would count as an improvement?

    Our provisional target is 20% fewer generated tokens with no more than a 3 percentage point drop in accuracy against relevant matched baselines. For example, 70% accuracy falling to 67% is a 3 percentage point drop. These are proposed criteria, not a measured outcome.

    We will count failed and unfinished answers too, compare the same test questions and report uncertainty. A fast, short answer that is wrong does not establish a useful improvement.

    Questions we asked along the way

    Where did the strangely specific 1,319 come from?

    It is the size of GSM8K’s official test split. We did not choose it. The dataset has 7,473 training questions and 1,319 test questions, totalling 8,792. The proposed 1,000, 300 and 200 groups are our subdivisions of the training pool.

    See GSM8K’s official dataset card.

    Why use only 1,000 training questions when more are available?

    To keep the experiment feasible. Preparing eight rewrites per question, checking them and training five conditions takes time. For the 1,000 training questions alone, that would mean up to 8,000 candidates and 16,000 two-attempt feedback completions, before additional checks. We will profile a 100-question pilot before deciding how far to expand.

    Why generate anything when GSM8K already has solutions?

    We can train on its existing solutions directly, and that is our required baseline. Rewriting creates a different format for the same answer, so we can test compact English and multilingual text. It does not create new questions or automatically make the solutions better.

    Why not use the most capable helper we have?

    We plan to try an available capable Claude or GPT model. But quality means more than fluent writing: a candidate must preserve the calculations, use fewer student-model tokens and remain useful to that student. A stronger helper is a good starting point, not proof of those properties.

    Does temperature zero make examples correct or fully repeatable?

    Temperature controls how much generation varies. Lower variation does not guarantee correct maths, the best compression or identical outputs across every software and hardware setup. We will save the checked examples and record model versions, prompts, seeds and settings. Candidate diversity can come from explicit rewrite formats and appropriate sampling.

    Is Qwen3-0.6B the same thing as a batch size?

    No. The model name describes the size of the model. A dataset size counts different training examples. A batch size counts examples processed together during training. We will choose the actual model and batch size from pilot measurements, rather than treating any proposed number as optimal.
